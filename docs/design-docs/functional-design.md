# Dockyard 功能设计

## 1. 产品边界

Dockyard 是 Node.js 应用的开发者本机守护工具，优化目标是**可诊断的本机开发**，而非生产部署。核心抽象固定为两层：用户导入一个目录作为 **Project**；Dockyard 在其中发现或由用户定义一个或多个可运行的 **Application**。

## 2. 功能模块

| 模块 | 职责 | 带给用户的结果 |
| --- | --- | --- |
| 发现与导入 | 选择文件夹、浅层/批量扫描、识别工作区/包脚本/PM2 生态文件、预览去重与转换 | 将散落的目录和已有 PM2 定义整理成准确目录 |
| 目录与配置 | 项目/应用元数据、command/cwd/环境变量白名单、标签、自启动和排序 | 不修改源码即可说明应用如何运行 |
| 守护器 | 创建进程、发现外部启动的目标进程、优雅终止、退出分类、重启状态机、退避和崩溃循环暂停 | 启动入口不影响守护资格，故障可见、可控且可恢复 |
| 日志管理器 | stdout/stderr 路由、轮转、保留期清理、基于游标的定位和 tail 订阅者 | 无需将日志写入数据库即可快速排障 |
| 可观测性 | 进程 CPU/RSS、运行时长、重启/退出次数、启动耗时、日志/磁盘体积 | 仪表盘直接回答什么不健康及其原因 |
| Web 体验 | 总览、项目详情、实时日志工作台、策略编辑器、设置、导入向导 | 低摩擦的人类运维体验 |
| CLI | 稳定 JSON/JSONL、退出码、安全的直接读取、通过守护进程执行变更 | 可靠的 Agent 自动化能力 |

## 3. 进程守护状态机

```text
stopped ── 启动 ──> starting ── 创建成功 ──> running
   ^                     │                        │
   └────── 停止 ─────────┴────── 停止 ────────────┤
                                              子进程退出
                                                   │
                            ┌──── 策略：重试 ─────┴──> restarting ──> starting
                            │
                            └──── 策略：暂停 ───────> crashed
```

守护器会在每次状态转换时记录生命周期事件，包括退出码/信号、已运行时长、策略决定和下一次重试时间。它还会以本机进程表和监听 socket 为边界，按已导入 Application 的工作目录发现从终端、IDE 或其他本机工具启动的 Node 进程；展示其 PID、运行来源和监听端口，并持续采样。外部进程消失而非用户明确停止时，按相同的重试预算和退避规则恢复。进程连续存活超过 `stableWindowMs` 后重置重试预算；预算耗尽则进入 `crashed`，**绝不**无限重启。停止操作先发送配置的优雅退出信号、等待，到期后仅在用户已配置允许的前提下升级为强制终止。外部进程的 stdout/stderr 不属于 Dockyard，日志视图不得声称能跟随它们。

## 4. 本机控制平面与 CLI 取舍

Nest 守护进程是唯一允许修改运行状态的进程所有者，提供回环 REST 接口和 SSE 事件流。Dockyard 是当前操作系统用户专用工具：**没有登录、账户、个人资料、角色或用户管理模型**。回环绑定、操作系统文件权限和仅守护进程持有的实例能力共同保护控制平面，不向用户暴露认证流程。

| 操作 | CLI 实现方式 | 原因 |
| --- | --- | --- |
| 读取静态配置、解析路径、查看本机可读日志元数据 | 直接调用共享读取适配器 | 最快且确定，不依赖守护进程 |
| 查询活动状态、指标、实时日志 tail | 调用守护进程查询/SSE | 守护进程是短暂运行时状态的事实源 |
| 导入、更新策略、启动、停止、重启、清理日志 | 调用守护进程命令端点 | 避免多进程所有者竞争，并保留审计事件 |

初始命令族：

```text
dockyard project scan <path> --json
dockyard project scan <path> --include-pm2 --json
dockyard import pm2 <ecosystem-file> --dry-run --json
dockyard project list --json
dockyard app status [id] --json
dockyard app start|stop|restart <id> --json
dockyard logs tail <app-id> --stream stdout|stderr --jsonl
dockyard diagnostics <app-id> --out <directory>
```

退出码 `0` 表示请求成功，`2` 表示输入无效，`3` 表示守护进程不可用，`4` 表示目标不存在，`5` 表示策略阻止了操作。JSON 按命令提供稳定的已文档化结构；日志跟随以每行一个 JSON 对象的 JSONL 输出。

### PM2 发现与转换

扫描器查找 `ecosystem.config.js`、`ecosystem.config.cjs`、`ecosystem.config.mjs`、`ecosystem.json`，以及 `package.json` 中的 PM2 段。它只解析声明式导出与静态字面量，**绝不执行**发现的配置文件。每个 PM2 `apps[]` 条目都会生成一个候选 Dockyard 应用，并显示逐字段转换预览：

| PM2 字段 | Dockyard 目标 | 说明 |
| --- | --- | --- |
| `name`、`cwd`、`script`、`args` | 应用名称、cwd、命令/参数 | 路径校验后原样导入 |
| `watch`、`ignore_watch` | 监听元数据 | 为未来监听器集成保存；不替代应用自身的 HMR 监听 |
| `autorestart`、`max_restarts`、`restart_delay`、`min_uptime` | 重启策略 | 直接映射或按规则换算单位 |
| `kill_timeout` | 优雅停止策略 | 换算为毫秒 |
| `out_file`、`error_file`、`merge_logs`、`log_date_format` | 日志策略候选 | 在预览中选择沿用 PM2 路径或使用 Dockyard 托管日志目录 |
| `env`、`env_*` | 环境变量差异 | 值默认掩码；每个键都需明确选择才可导入，默认不持久化 |

`instances`、`exec_mode`、部署钩子和 PM2 模块等集群/生产专用设置会被标记为不支持，而不是静默近似转换。用户可导入已接受的行、编辑或丢弃预览；原始 PM2 文件永不修改。

## 5. 持久化与文件布局

SQLite 只保存持久记录。建议表为：`projects`、`applications`、`application_commands`、`restart_policies`、`log_policies`、`configuration_revisions`、`lifecycle_events`、`metric_rollups_hourly`、`metric_rollups_daily` 和 `schema_migrations`。原始指标样本存放于有界内存环形缓冲区后再聚合；高频日志行绝不写入数据库。

```text
<state-dir>/
  dockyard.sqlite
  logs/<project-id>/<app-id>/{stdout,stderr}.log
  logs/<project-id>/<app-id>/archive/*.log.gz
  runtime/<app-id>.pid
  diagnostics/<timestamp>-<app-id>/
```

日志轮转综合最大字节数、最大文件数和保留天数。清理在启动时和每日计划任务中运行，不会删除正在写入的文件，并发布包含释放字节数的生命周期事件。UI 脱敏仅是显示转换；原始本机日志保持不变。

## 6. Web 信息架构

| 视图 | 主要信息与操作 |
| --- | --- |
| 运行总览 | 全局状态、关注队列、CPU/RSS 趋势、重启趋势、活动日志片段 |
| 项目 | 导入、批量扫描、PM2 转换预览、列表/树、项目级健康度和批量操作 |
| 排障中心 | 崩溃队列、生命周期时间线、退出原因、选定诊断操作，以及跳转到相关日志位置的链接 |
| 项目详情 | 发现的应用、命令、最近退出、标签和安全的环境配置 |
| 应用详情 | 状态时间线、指标、策略、启动/停止/重启和诊断导出 |
| 实时日志 | 流选择器、跟随/暂停、级别/文本过滤、时间戳定位、复制/导出 |
| 报表 | 可用性、重启、启动耗时、资源峰值、日志增长 |
| 设置 | 状态目录、保留期、策略预设、主题、语言和守护进程健康度；绝不包含账户或访问控制 |

侧栏严格只有五个一级入口：运行总览、项目、排障中心、日志和报表；设置是位于底部的小型操作。浅色主题中，侧栏与内容区使用同一白色/近白色表面体系，以细微分隔线和蓝色选中态建立层级。Semi Design 提供导航、表格、表单、模态框、标签、空状态和反馈组件。应用在本机持久化语言与主题；中英文文案使用带稳定消息键的版本化词典。当前参考视觉稿见 [`assets/ui/dockyard-dashboard-light-v3.png`](../../assets/ui/dockyard-dashboard-light-v3.png)。

## 7. 指标与报表

按应用以可配置间隔（默认 5 秒）采样的当前指标包括：CPU 百分比、RSS、进程树数量、运行时长、可选探针提供的事件循环延迟、日志字节数、重启次数、退出原因和启动耗时。报表基于聚合数据，而不是扫描原始日志：

- 健康度：可用性、崩溃循环数量和平均恢复时间；
- 性能：CPU/RSS p50/p95/max、峰值时刻和资源趋势；
- 开发反馈：重启原因分布、启动耗时趋势和噪声日志体积；
- 存储：按应用统计日志保留量和清理节省空间。

## 8. 安全与防护

- 默认只绑定回环地址；MVP 不提供云端同步。
- 将导入的 `package.json` 和脚本字符串视为不可信数据；首次启动前展示精确命令和工作目录。
- 默认使用 `shell: false`、显式参数数组、受限继承环境和脱敏后的展示值。
- 不在 SQLite 或报表中存储原始密钥值；在设计好加密本机存储前，不持久化任意环境变量。
- CLI 的破坏性操作必须指定目标 ID；Web 中必须确认，并保留事件记录。

## 9. 实施计划与发布门槛

| 阶段 | 垂直切片 | 退出门槛 |
| --- | --- | --- |
| 0 — 基础 | 工作区、文档系统、守护进程健康检查、Web 壳、CLI 壳 | `pnpm check` 与构建通过 |
| 1 — 目录 | SQLite 迁移、文件夹扫描预览、PM2 静态解析/转换预览、项目/应用 CRUD、导入 UI/CLI | 重复导入保持幂等；PM2 文件从不被执行或修改；重启后配置可恢复 |
| 2 — 守护 | 类型化进程创建适配器、生命周期状态机、重启策略、事件时间线 | 人为触发崩溃后得到可解释且有上限的恢复 |
| 3 — 日志 | 文件写入器、轮转、过滤/搜索、SSE tail 和 CLI JSONL | 长时间 tail 的内存有界，且不插入数据库日志行 |
| 4 — 可观测性 | 采样器、聚合、总览和报表 | 守护进程重启后仍可按聚合精度查看指标 |
| 5 — 加固 | 诊断导出、脱敏测试、崩溃恢复、无障碍/国际化/主题 QA | 关键旅程通过自动化与人工验收 |

每个阶段都要在 `docs/exec-plans/active/` 中创建计划，包含验收标准、决策日志、验证命令和迁移说明。完成后原样移入 `completed/`；延后事项记录进债务追踪器。CI 将从现有文档/类型检查逐步扩展为单元、集成、架构边界和端到端检查。
