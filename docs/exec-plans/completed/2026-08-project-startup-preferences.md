# 项目启动偏好与根入口执行计划

## 目标

让 `Project` 而非单个 `Application` 决定一键生命周期动作的入口，兼容 monorepo 以根脚本一次编排多个模块的开发方式，同时保留模块级启动的控制权。

## 交付与验收

1. 扫描根 `package.json` 时静态发现 `dev`、`start`、`serve` 和 `*:dev` / `*:start` / `*:serve` 项目入口；workspace 根不再因为是编排目录而被忽略。
2. 项目设置保存启动偏好（`automatic`、`project-first`、`module-first`）、候选入口与选定入口，并对旧设置安全回填为自动模式。
3. 自动模式在存在选定入口时启动根入口，否则启动模块集合；项目优先在没有入口时明确拒绝；模块优先保持逐模块行为。
4. 守护进程创建项目入口时使用独立进程组，项目停止/重启对整个组请求 `SIGTERM`；入口退出沿项目重启策略恢复。
5. 项目设置明确解释入口与模块集合的职责，项目 SSE 状态可刷新页面。

## 决策

- 启动偏好是项目管理策略，不是进程发现过滤器；外部运行模块仍按真实 cwd/进程树观察。
- `automatic` 不把所有 workspace 包假设为必需服务，只有选定根入口明确存在时才以项目入口启动。
- 项目级 stdout/stderr 暂不伪装成模块日志；模块日志仍仅来自守护进程实际捕获的模块子进程。

## 验证

已运行 `pnpm test`、`pnpm check`、`pnpm docs:check`，覆盖 workspace 根入口发现、持久化启动偏好和既有扫描/数据库回归。
