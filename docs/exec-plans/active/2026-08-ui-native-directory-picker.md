# UI 重建与本机目录选择执行计划

## 目标

将 Dockyard 从可点击的原型提升为可验收的本机运维界面，并在项目扫描中提供操作系统原生目录选择。

## 交付范围

1. 五个一级入口呈现各自的真实工作流：总览、项目、排障、日志、报表。
2. 空状态提供明确的引导，而不是空白画布；已导入应用展示真实 API 数据。
3. 扫描弹窗可通过守护进程调用本机目录选择器，并保留手输绝对路径的回退方式。
4. 目录选择器不执行项目代码、不发送目录内容，并在取消时返回空结果。
5. 使用浏览器进行视觉与交互验收；运行 `pnpm check`、`pnpm test`、`pnpm build`。

## 平台策略

- macOS：`osascript` 的 `choose folder`；
- Windows：PowerShell `FolderBrowserDialog`；
- Linux：优先 `zenity --file-selection --directory`，不可用时明确返回可恢复错误。

所有命令均以显式参数、`shell: false` 的方式由守护进程执行。原生对话框仅返回用户选择的本机路径。

## 决策日志

- 不引入 Electron 或云端文件选择服务；目录对话框是守护进程的本机适配器。
- Linux 缺少 `zenity` 时保留手输路径，并返回带恢复说明的错误。
- 页面不伪造资源图表：只有从守护进程读取到聚合数据时才展示数值。
- 全局保留/限制和策略预设保存在 SQLite 的版本记录中；在事务内更新现有应用，并由运行时刷新活跃实例，后续导入也继承该配置。
- 主题与语言仅保存在浏览器本机存储；中英显示由版本化消息目录控制，不创建账户或网络同步。
- 停止操作默认只请求优雅的 `SIGTERM`；五秒未退出时保持进程可诊断并返回超时，不会在未明确配置授权的情况下升级为 `SIGKILL`。

## 迁移说明

早期原型使用了与当前仓储不兼容的 SQLite 表列。启动时会检测旧 `applications` 表，读取项目、应用、事件和指标数据，在事务内重建当前模式并重新写入兼容字段；无需删除用户状态目录。升级前建议保留状态目录副本，旧版本二进制不能再读取升级后的数据库。
