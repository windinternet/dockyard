# 项目编排、应用策略与运行时指标执行计划

## 目标

将 Project 固定为代码库目录，将 Application 固定为目录内可运行模块；让项目能批量编排模块、解析静态 PM2 候选、管理各模块策略，并提供可信运行指标。

## 交付与验收

1. Project 启动/停止/重启会按其 Application 集合请求守护进程操作；CLI 支持 `dockyard start <project>` 和 `dockyard start <project>:<module>`。
2. Project 删除需要明确确认，先安全停止托管模块，再删除 SQLite 元数据；日志文件保留在本机，绝不删除未确认的目录或源码。
3. Application 的重启和日志策略可由受类型校验的 API 更新，并即时刷新活动运行时。
4. 运行中的 Application 默认每 1 秒采样 PID、CPU 百分比、RSS、运行时长与重启数；该频率可在本机设置中调整并即时生效，报表只展示实际采样值。
5. 侧栏导航不溢出其固定宽度，窄屏仍可用。
6. 每个可运行 package 模块只导入一个 Application；它保存可选启动命令并优先使用 `dev`。项目页将模块直接嵌入所属项目，并由项目设置管理一键启动集合、守护与日志规则。

## 决策

- 模块优先时，项目级命令由守护进程编排其应用集合；选定项目入口时，则由守护进程执行根命令并拥有该入口进程组。CLI/Web 始终不直接创建子进程。
- 仅删除 Dockyard 元数据；项目源码、原始日志和选择的目录不会被删除。
- CPU/RSS 在 POSIX 平台使用带固定参数的 `ps` 查询；其他平台返回 `null`，不伪造指标。
- 策略更新在 SQLite 事务中写入后刷新运行时应用快照；后续导入继承全局默认，单个应用可再覆盖。
- 项目设置保存为该项目的新模块默认策略与一键启动编排；现有模块保留其独立策略，避免静默覆盖 PM2 映射或人工调整。

## 验证

运行 `pnpm test`、`pnpm check`、`pnpm docs:check`，并在浏览器中验证项目批量启动、策略编辑、删除确认、指标展示和侧栏布局。
