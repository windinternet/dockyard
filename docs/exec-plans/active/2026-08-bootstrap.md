# 仓库初始化与 MVP 实施计划

## 目标

建立稳定的项目结构，使 Dockyard 能够通过相互独立的垂直切片持续实现，同时不丢失产品和架构上下文。

## 已作决策

- 使用 pnpm 工作区，包含 NestJS 守护进程、React/Semi Web 应用和独立 CLI 包。
- SQLite 隔离在 `packages/db` 后；日志内容保留在文件中。
- Web 与 CLI 的写操作都收敛到守护进程命令服务；只有安全读取可以使用直接本机适配器。
- Dockyard 是当前操作系统用户使用的本机工具：没有登录、账户、个人资料、RBAC 或用户管理子系统。
- 项目扫描提供安全的 PM2 迁移通道：解析静态生态配置，预览映射/告警，绝不执行或修改配置文件。
- 开发和生产的 Web 面板都由同一个 Nest 守护进程托管：开发时内嵌 Vite，生产产物由守护进程直接提供；CLI 以全局 `dockyard` 命令安装。

## 交付顺序

1. 建立仓库、文档地图和 CI 检查。**进行中**
2. 实现项目发现/导入预览、安全 PM2 转换预览和 SQLite 迁移。
3. 实现应用配置和受监管的生命周期状态机。
4. 实现结构化生命周期事件、文件日志写入/轮转和 SSE tail。
5. 同步构建运维 Web 视图与 CLI JSON 契约。
6. 补充指标采样、报表、诊断导出和加固。
